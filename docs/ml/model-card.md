# Model card: Vaulta merchant categoriser

Generated by `ml/report.py` from `ml/artifacts/metrics.json`; details and plots in [evaluation.md](evaluation.md).

**Status: shipped (Model A).**

## What it does

Given a bank narration as Vaulta stores it (personal details already stripped), it predicts one of the
130 subcategories in [taxonomy.md](taxonomy.md); the category group follows from the subcategory. In the
app it runs after the user's rules, the user's own similar corrections and known merchants, and only above its
threshold (0.72); everything else goes to the review queue (`backend/app/services/categorizer.py`).

- **Model:** character 1–5-gram TF-IDF + multinomial logistic regression (C = 3.0), 21542 n-grams,
  int8 weights, temperature 0.752. 4.3 MB as JSON, ~0.75 MB gzipped.
- **Where it runs:** in the browser for statement imports (`frontend/src/lib/merchantModel.js`, the file served by
  Vaulta itself and cached by the service worker), and on Vaulta's server for alert emails, manual entries and
  Telegram. Both use the same file; tests check they give identical answers.
- **Switch:** `MERCHANT_MODEL_ENABLED=false` returns the app to the rule-based categories.

## Training data and labels

- **No user data.** 5032 merchants: a hand-written catalogue of Indian brands and
  generic descriptors, plus generated local shops. 19615 synthetic narrations in Indian bank
  formats, passed through Vaulta's PII stripper. No real statements were used (`local-statements/` was empty).
- **Labels: knowledge distillation.** Two LLMs on Groq (`openai/gpt-oss-120b`, `qwen/qwen3.8-27b`, `openai/gpt-oss-20b`) labelled each
  stripped merchant name, with a third model breaking ties. Names with no majority (731) were dropped.
  Only merchant names were sent, never transactions. At least 179 LLM calls.
- **All metrics are agreement with these teacher labels, not accuracy.** No human-verified labels exist.

## Limits

- Every number is measured on **synthetic** narrations against **LLM** labels; real narrations and the teacher's own
  mistakes are not measured. Synthetic test merchants are unseen *names* but come from the same generator.
- On unseen brands the model can only use the shape of the name. Known merchants and the model together file
  42.2% of unseen-merchant narrations and agree with the teacher on 84.5% of those, below the 90% the
  model's threshold was tuned to on validation.
- Bank narrations of payments to *people* can be filed by the remark ("Rent"), as the rules already did
  (see evaluation.md). UPI-app payments to people never reach the model.
- English-script narrations only were generated; the model has not been tested on other scripts.

## Personalisation, monitoring and retraining

- A user's own correction applies to similar narrations from then on (only theirs), and to every narration from the
  same merchant once a rule is learned. Explanations are shown on tap.
- `GET /internal/model-metrics` reports daily counts of categorised and corrected rows per source, across all users,
  with no merchant or user.
- Users can opt in (Settings → Categories) to let their corrections retrain the model; `ml/retrain.py` keeps a new
  model only if it isn't worse on the frozen test sets and on corrections held out from training.
