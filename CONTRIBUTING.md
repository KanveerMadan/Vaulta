# Contributing

Thanks for looking. vaulta.in is a small project with one maintainer, so issues and small pull requests are the
easiest to take in.

## Set up

Follow the [README's quickstart](README.md#local-development): Python 3.12, Node 22, a local Postgres, and Java 21+
for the Firebase Auth emulator. No real keys or accounts are needed: local runs use generated keys, the Auth emulator
and a fake LLM.

## Branches and pull requests

1. Branch off `main` (`feat/…`, `fix/…`, `chore/…`, `docs/…`). Don't commit to `main`.
2. Keep a pull request to one change, and say in its description what changed and how you checked it.
3. CI must pass: backend tests and migrations, frontend lint, unit tests and build, browser tests, the email worker's
   tests, the merchant-model data check and the security checks (`.github/workflows/ci.yml`).
4. The maintainer reviews and merges. Merging to `main` deploys to production (`docs/DEPLOY.md`).

Pushed branches are never rebased or force-pushed; bring `main` in with a merge.

## Tests

```sh
cd backend && venv/bin/python -m pytest -q          # needs the local Postgres (README)
cd frontend && npm run lint && npm test             # unit tests (Vitest)
cd frontend && npx playwright test                  # browser tests; starts the emulator, API and app itself
cd infra/email-worker && npm test
```

A change that touches a privacy or security claim on /security (`frontend/src/lib/trust.js`) must change the code and
its test together. A new text column must be encrypted or justified (`backend/tests/test_encryption.py`).

## No secrets, no real data

- Never commit secrets, keys, tokens, `.env` files, database URLs or service-account files. `.gitignore` covers the
  usual ones; run `scripts/secret-check.sh HEAD` before you push.
- Never commit real bank statements, alert emails or anyone's transactions. Test data is synthetic
  (`fixtures/statements/`, generated by `fixtures/statements/make_fixtures.py`). Keep real files for local testing in
  `local-statements/`, which is ignored.
- Never point tests at a non-local database: the test suites refuse to.
